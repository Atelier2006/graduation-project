# 品質チェックリスト

卒業制作Ⅱでは技術面の評価の割合が高くなります。実装中・テスト時・展示会前にこのリストで確認してください。

## 認証

- [ ] パスワードを平文でDBに保存せず、ハッシュ化している（できればソルト付き）
- [ ] ログイン後のセッションを保持している（トークンでも可）

## APIキー管理（WebAPIを使う場合）

- [ ] APIキーをHTMLやJavaScriptに直接書いていない（サーバー側だけが知る秘密にする）
- [ ] APIキーは `.env` などの設定ファイルや環境変数に置き、ソースコードと分けている
- [ ] `.env` をGitにコミットしていない

## データベース

- [ ] すべてのテーブルに主キー（`id`）がある
- [ ] テーブル同士の関係を外部キー（`user_id` など）で表し、外部キー制約を付けている
- [ ] 重複してはいけない項目にユニーク制約を付けている
- [ ] 必須項目に `NOT NULL` を付けている
- [ ] 同じ情報を複数のテーブルに重複させていない
- [ ] テーブルが3つ以上ある

## UI（モバイルファースト）

- [ ] フォームが簡潔
- [ ] ボタンが指で押しやすいサイズ
- [ ] 色に意味を持たせている（赤：警告、緑：成功）
- [ ] 文字が小さすぎない
- [ ] 横スクロールが出ない

## JSアニメーション

- [ ] 軽く、元に戻せる（CSSアニメーション＋少しのJS）
- [ ] 派手すぎず、処理が重くならない

> 例：登録成功 → ふわっと表示、警告 → 揺れる、データ更新 → 色が変わる

## ログ・エラー処理

- [ ] API失敗・タイムアウトを監視ログに記録している
- [ ] 失敗しても画面が真っ白にならない
- [ ] 通信エラー時に「通信に失敗しました」などのメッセージを表示する
- [ ] エラー内容をログに残している

## テスト

「テスト＝動くか確認」ではありません。次のすべてを試します。

- [ ] APIモックを用意し、オフラインでも動作を検証できる
- [ ] 正しい操作
- [ ] 間違った操作（空欄で送信、長すぎる文字など）
- [ ] 想定外の入力

## セキュリティ

- [ ] **XSS**：画面に表示する前にエスケープ（無害化）している
- [ ] **SQLインジェクション**：プレースホルダ（Prepared Statement）を使っている
- [ ] **ディレクトリトラバーサル**：
  - [ ] ファイル名を直接指定させていない
  - [ ] DBには「ファイルID」を保存し、実際のパスはサーバー側で決めている
  - [ ] 許可した拡張子だけを扱っている

## スコープ管理

学生制作でいちばん多い失敗は「作りたいものが増えすぎる」こと。**完成しない100点より、完成した80点。**

- [ ] 必須機能を最初に決めた
- [ ] 追加機能は時間が余ったときだけ作る
- [ ] 外部APIは1つに絞って深掘りする

## 展示会前

展示会でよく起きること：ネットが遅い／操作されすぎる／説明時間が短い

- [ ] デモ用アカウントを用意した
- [ ] デモ用のサンプルデータを事前に投入した
- [ ] 通信がなくても最低限動く画面を試した
- [ ] 「ここを押してください」が分かる画面になっている
- [ ] 見せ場（アニメーション・グラフ）を決めた
