## 1. 案の出し方

これまでの案と重ならないよう、次の3つの方向から考えた。

1. **チームの身近な人が本物のユーザーになるもの**：クラスメイト（この授業でプレゼンが3回ある）、家族（詐欺の被害が心配な親・祖父母）、後輩（基本情報技術者試験の勉強中）。
2. **いま社会で問題になっていること**：フィッシング詐欺の報告件数は、2024年に171万8,036件で過去最多になった。金融リテラシー調査（2025年）では、全体の正答率が53.8%で前回（55.7%）より下がった。
3. **まだ使っていない第2階層・第3階層の組み合わせ**：WebAssembly（ブラウザ内でSQLiteを動かす）、3D表示、地域社会・観光・企業業務など。

条件で除外した案：

| 案 | 除外した理由 |
| --- | --- |
| バリアフリー情報マップ | 実地調査と、当事者（車いす利用者など）の協力が必要 |
| 位置情報を使うゲーム（歩いてスタンプを集めるなど） | GPSの動作を実機で確かめる必要があり、Claudeが検証できない |
| 音楽ゲーム | 楽曲の著作権の扱いが難しい |
| 育児記録 | 子どもの個人情報を扱い、クラスに想定ユーザーがいない |
| 自治体の公開データを使う生活情報（ゴミ分別など） | 地域ごとにデータの形式がばらばらで、整える手間が大きい |

## 3. 上位3案の詳細

### 3.1 ネット詐欺見抜きトレーニング（仮称：ミヌケル）— 89点

**一言**：本物そっくりに作った架空のメール・SMS・SNSのメッセージ・Webサイトを見て、「本物か詐欺か」を判定する。1問ごとに「どこを見れば見抜けたか」を解説し、苦手な手口を分析する。

**背景**

- フィッシングの報告件数は2024年に171万8,036件で過去最多。2025年はさらに増えたと報じられている。
- 見た目がそっくりな文字を使った偽のURLは、普通のフィッシングURLよりだまされやすいという研究がある（2020年のGoogleとイリノイ大学の共同研究を紹介した記事では、約6割がだまされたのに対し、普通のフィッシングURLでは約7%）。
- SNSを使った投資詐欺も増えていると、金融経済教育推進機構（J-FLEC）の講演資料で指摘されている。

**想定ユーザー**

- メイン：スマホを使う18歳以上の人（学生・社会人）。
- サブ：家族（親・祖父母）に注意を呼びかけたい人。社員研修や授業で使いたい人。

**困りごとと解決策**

| 困りごと | 解決策 |
| --- | --- |
| どこを見れば見抜けるのか分からない | 1問ごとに「見るべき場所」（送信元、URL、急がせる文言など）をハイライトして解説する |
| 自分がどの手口に弱いか分からない | 手口ごとの正答率を出し、苦手な手口を重点的に出題する |
| 家族に注意しても伝わらない | 同じ問題セットを「挑戦状」として送り、結果を比べられる |
| 新しい手口が次々に出てくる | 利用者が「こんなのが来た」と投稿し、管理者が確認して問題にする |

**3階層**：安全（主）、学べる・楽しい（副） × データ分析・データの可視化（主）、WebAPI開発（副） × 地域社会（主）、学生生活（副）

**機能**

| 区分 | 内容 |
| --- | --- |
| 必須（MVP） | 問題（メール・SMS・SNS・Webサイトの画面をHTMLで再現。会社名はすべて架空）、10問チャレンジ、見るべき場所の解説、手口のタグ、成績の履歴、苦手な手口、ランキング、問題へのコメント、全体の統計（手口ごとのだまされた率）、管理サイト |
| 追加 | 難易度の自動調整、URLの読み方トレーニング、家族への挑戦状、利用者の投稿、展示会モード（年代別の結果を大画面に表示） |

**保存・共有・分析との対応**

| 必須機能 | 実装 |
| --- | --- |
| 保存 | 成績の履歴、苦手な手口の一覧、お気に入りの問題、マイページ |
| 共有 | ランキング、問題へのコメント、挑戦状、利用者の投稿 |
| 分析 | 手口ごとのだまされた率、問題の難しさ、自分の見抜く力の推移、年代別の正答率（年代の入力は任意） |

**主なテーブル**：users、cases（問題）、tactics（手口）、case_tactics、hints（見るべき場所）、plays（挑戦）、answers（回答）、submissions（投稿）、comments、favorites、challenges（挑戦状）

**技術の見どころ**

1. **問題の難しさを自動で数値化**：対戦のレーティング（イロレーティング）を「人と問題の対戦」に応用する。多くの人が間違える問題ほど難しい値になり、利用者の実力に合った問題を選んで出せる（適応型の出題）。
2. **URLの解析**：URLの末尾側にある「本当のドメイン」を取り出して強調する。国際化ドメインの `xn--` で始まる表記（Punycode）を元に戻す。Unicodeが公開している「見た目が紛らわしい文字」のデータ（UTS #39）を使い、そっくりな文字を使った偽ドメインを見つける。
3. **安全な画面の再現**：問題の画面はHTMLを直接保存せず、送信元・件名・本文・リンクの文字などの項目ごとにDBへ保存し、テンプレートで組み立てる。利用者の投稿は文字だけを受け付ける（XSS対策の説明そのものになる）。
4. **集計と可視化**：手口別・年代別の正答率をSQLで集計し、Chart.js で描く。

**展示会**：「あなたは見抜ける？10問チャレンジ」（2〜3分）。大画面に「来場者の◯%がだまされた問題」「年代別の正答率」を表示する。保護者や祖父母の世代に響きやすい。外部APIを使わないので、ネットなしで動く。

**ユーザー調査**：10月にアンケート（怪しいメッセージを受け取った経験、普段どう確かめているか）。12〜1月にクラスメイトと、その家族にも試してもらう。2月にSUS（使いやすさの点数）と、1回目と2回目の正答率の変化を測る。

**似たサービス**：Google（Jigsaw）のフィッシングクイズ（2019年公開、日本語の紹介記事あり）。公的機関の注意喚起ページ。こちらは、日本で多いSMS・SNS・投資詐欺の手口を扱い、苦手の分析・難易度の自動調整・家族への挑戦状・利用者の投稿で差を付ける。

**注意点**

- 実在の企業名・ロゴ・URLは使わず、すべて架空にする。問題内のリンクを押しても外部のサイトには飛ばないようにする。
- 手口の説明は、フィッシング対策協議会や警察などの公的な注意喚起を参考に、正確に書く。
- 内容は「見抜き方」に絞り、だます側のやり方を教えるものにしない。

### 3.2 プレゼン相互評価（仮称：ハッピョウボード）— 88点

**一言**：発表を聞いた人が、QRコードから参加してスマホで観点ごとに採点・コメントする。発表者はその場でレーダーチャートとコメントを受け取り、練習ごとの成長も見られる。

**背景**

- この授業では計3回のプレゼンがあり、他クラスの学生が観点ごとに評価する（[概要説明](overview.md#プレゼン)）。
- 大学の授業でも、評価結果の返し方は紙・表計算ファイル・学習管理システムなどばらばらで、教員ごとに工夫しているという報告がある。
- 評価を匿名にすると、評価される側に気兼ねせずに正直に採点できる、という報告もある。

**想定ユーザー**：発表の練習をする学生・新入社員。発表会を運営する先生・研修担当者。

**困りごとと解決策**

| 困りごと | 解決策 |
| --- | --- |
| 紙の評価シートを集計するのが大変 | スマホで入力し、その場で自動集計する |
| フィードバックが遅い、届かない | 発表が終わった瞬間に結果を見られる |
| 自分の癖が分からない | 観点ごとのレーダーチャートと、自己評価と他人からの評価の差を見せる |
| 成長が見えない | 練習ごとの点数の推移を見せる |

**3階層**：コミュニケーション（主）、便利（副） × WebAPI開発・データ分析・データの可視化 × 学校（主）、企業業務（副）

**機能**

| 区分 | 内容 |
| --- | --- |
| 必須（MVP） | 発表会の作成、評価の観点（ルーブリック）のテンプレート、QRコードで参加（ログイン不要・1人1回）、観点ごとの採点とコメント、自己評価、発表者向けの結果（レーダーチャート・コメント）、自分の発表の履歴と推移、テンプレートの共有と人気ランキング、全体の統計 |
| 追加 | 大画面での即時集計表示、不適切なコメントの自動チェック、主催者向けのCSV出力、評価者ごとの「甘い・辛い」の癖の補正 |

**保存・共有・分析との対応**

| 必須機能 | 実装 |
| --- | --- |
| 保存 | 自分の発表の履歴、受け取った評価、お気に入りのテンプレート |
| 共有 | テンプレートの公開と人気ランキング、発表へのコメント |
| 分析 | 観点ごとのレーダーチャート、練習ごとの推移、自己評価と他人からの評価の差、評価のばらつき |

**主なテーブル**：users、events（発表会）、presentations（発表）、rubrics（評価の観点のセット）、rubric_items（観点）、evaluations（評価）、evaluation_scores（観点ごとの点数）、rubric_favorites、comment_reports（不適切なコメントの通報）

**技術の見どころ**

1. **1人1回の評価**：ログインなしでも二重に評価できないよう、端末ごとの識別情報をハッシュ化して保存する。評価は匿名のまま扱う。
2. **評価者の癖の補正**：いつも高い点を付ける人、低い点を付ける人の差を、標準化（平均と標準偏差でそろえる計算）で補正する。
3. **即時の集計**：評価が入るたびに、大画面のグラフが数秒ごとに更新される。
4. **QRコードの生成**：発表会ごとに参加用のQRコードを作る。

**展示会**：スタッフが30秒の自己紹介をし、来場者がタブレットで採点すると、大画面のレーダーチャートがその場で動く。

**ユーザー調査**：チーム同士の発表練習（リハーサル）で、実際に評価し合うのに使う。授業の本番でも使えるかは、担当教員に相談する。

**似たサービス**：大学で独自に作られた相互評価システムの研究報告が多い。実際の授業では、Googleフォームや学習管理システムで代用されることが多い。Mentimeter や Slido は投票や質問の受け付けが中心。こちらは観点ごとの評価と、発表者への即時のフィードバック、成長の記録に特化する。

**注意点**：悪口のようなコメントへの対策（不適切な言葉のチェック、通報）。授業の本番で使うなら教員の了承が必要。教室で参加者のスマホからつなぐネットワーク（チームのWi-Fiルーターなど）。

### 3.3 積立・分散を体験する投資シミュレーションゲーム — 87点

**一言**：架空の市場で、20年分の値動きを数分で体験する。毎年の積立額と、株式・債券・預金の配分を選び、暴落も経験する。結果をランキングと散布図で比べる。

**背景**

- 金融リテラシー調査（2025年、18〜79歳の3万人）では、全体の正答率が53.8%で、2022年の55.7%より下がった。30代以下では投資の経験が広がっている一方、金融経済教育を受けたと答えた人は8.7%にとどまる。
- 若い世代ほど、自分の知識への自己評価と実際の正答率の差（「金融リテラシーギャップ」）が広がっていると指摘されている。

**想定ユーザー**：投資に興味はあるが怖いと感じている、18歳以上の初心者。もうすぐ社会人になるクラスメイト。

**困りごとと解決策**

| 困りごと | 解決策 |
| --- | --- |
| 長期・分散の効果が実感できない | 20年分を数分で早送りして体験する |
| 暴落のときに慌てて売ってしまう | 暴落を体験し、売った場合と持ち続けた場合の結果を比べる |
| 1人では続かない | 同じ条件の市場で、友達と結果を競う |
| 用語が難しい | ゲームの中で、その場で用語を解説する |

**3階層**：学べる（主）、楽しい（副） × データ分析・データの可視化 × 学生生活

**機能**

| 区分 | 内容 |
| --- | --- |
| 必須（MVP） | 架空の市場（株式風・債券風・預金の3種類）、毎年の配分と積立額の選択、暴落などの出来事、結果画面（資産の推移、年あたりのリターン、最大の下落率）、履歴、同じ条件の中でのランキング、戦略へのコメント、全体の統計（戦略ごとの結果の散布図） |
| 追加 | 部屋を作って友達と同時にプレイ、結果カードの共有、「必ずもうかる」などの詐欺の誘い文句を見抜くミニクイズ |

**主なテーブル**：users、scenarios（市場の条件と乱数の種）、rooms（対戦の部屋）、games（プレイ）、decisions（毎年の選択）、comments、favorites、terms（用語）

**技術の見どころ**

1. **値動きのシミュレーション**：平均的な上昇率と値動きの大きさから乱数で値動きを作る、標準的なモデル（幾何ブラウン運動）に暴落の出来事を加える。
2. **公平な対戦**：乱数の種（シード）をそろえて、全員に同じ市場を再現する。同じ種なら必ず同じ結果になることをテストで確かめる。
3. **指標の計算**：年あたりのリターン、標準偏差（リスク）、最大ドローダウン（最大の下落率）、シャープレシオ（リスクあたりのリターン）。
4. **不正の防止**：ブラウザから送られた結果は信用せず、毎年の選択の記録と乱数の種から、サーバー側で計算し直す。結果はいつでも計算し直せるので、DBに重複して保存しない。

**展示会**：「20年で資産をいくらにできる？3分チャレンジ」。大画面にランキングと、戦略ごとの結果の散布図を出す。保護者の世代に響きやすい。外部APIを使わず、ネットなしで動く。

**似たサービス**：日本証券業協会などの「株式学習ゲーム」（実際の株価で1か月以上かけて模擬売買する学校向け教材）、J-FLECの中高生向け教材、資産運用を学ぶゲームアプリ（多数）。こちらは架空の市場で長期を数分に縮めること、同じ条件での対戦、暴落時の行動の体験で差を付ける。

**注意点**：特定の金融商品や銘柄を勧めない（J-FLECも同じ立場を示している）。実在の指数や商品の名前を使わない。「将来の利益を約束するものではない」と表示する。リスク（下落）も必ず見せ、投資をあおる演出にしない。

## 4. 注目の次点

### 4.1 擬似言語ステップ実行（基本情報 科目B）— 86点

- **内容**：基本情報技術者試験・科目Bの擬似言語で書かれたプログラムを1行ずつ動かし、変数や配列の変化を目で追う。動かした記録から「3回目のループで変数 x の値は？」のような問題を自動で作る。
- **強み**：IT専門学校の教員とクラスメイトに強く響く。擬似言語を読んで動かす仕組み（字句解析・構文解析・実行）は技術的に深く、Claude がテストで確かめやすい。
- **弱み**：同じように1行ずつ動かせるツールが、すでに複数ある（擬似言語ステッパー、Giji Academy、個人開発の記事など）。差を付けるなら、自動作成の問題と学習の分析。擬似言語を知らない展示会の来場者には伝わりにくい。

### 4.2 SQL練習場 — 85点

- **内容**：SQLiteをWebAssemblyでブラウザ内に動かし（sql.js）、利用者が書いたSQLの結果を正解と比べて自動で採点する。問題は利用者も作って共有できる。
- **強み**：SQLはブラウザの中だけで動くので、サーバー側に危険が生じにくい。データベースの授業との相性が良い。
- **弱み**：展示会でSQLを知らない来場者には伝わりにくい。

### 4.3 卒業旅行の計画と割り勘の精算 — 83点

- **内容**：旅行の行程表、持ち物リスト、立て替えたお金の記録。最後は「誰が誰にいくら払えば済むか」を、送金の回数が少なくなるように計算する。
- **強み**：2〜3月の卒業旅行の時期と重なり、クラスメイトが本物のユーザーになる。精算のアルゴリズムが説明しやすい。
- **弱み**：割り勘アプリや旅のしおりアプリはすでに多い。

### 4.4 こどもプログラミング・パズル — 82点

- **内容**：ブロックを並べてキャラクターをゴールまで動かすパズル。ステージは利用者が作って共有できる。
- **強み**：展示会で子どもと保護者が集まりやすい。最短手数を自動で計算する（幅優先探索）ので、公平なランキングが作れる。
- **弱み**：クラスメイトは本当の想定ユーザー（子ども）ではない。Scratch など有名な教材が多い。
