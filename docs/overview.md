# 2026年度 後期 卒業制作Ⅱ 概要説明

2026年10月8日 Ver 1.00

## 目的

- 3年間の学習の集大成
- チームで開発することで、社会人としてのコミュニケーション能力を身につける
- 卒業単位の認定（習得した技術を反映し、何らかの商業的・社会的価値を想定したもの）
- 2027年2月ごろに展示会を開き、来場者や保護者が自分の作品に触れる機会を作る

## 企画テーマ

第1階層 → 第2階層 → 第3階層 からそれぞれ1つ以上選び、システム・サービスを開発する。

> 例：第1階層「問題解決」、第2階層「WebAPI開発」、第3階層「学生生活」→ 図書館書籍検索アプリ
>
> ※1チームのみ、卒業アルバム的なシステムと2月展示会の企画運営などを担当する。

| 第1階層：ユーザー価値 | 第2階層：技術要素 | 第3階層：対象分野 |
| --- | --- | --- |
| 楽しい | AI・生成AI | 学校 |
| 便利 | 機械学習 | 学生生活 |
| 問題解決 | データ分析・データの可視化 | 地域社会 |
| 学べる | IoT / ハードウェア利用（ラズベリーパイ・Arduinoの貸し出し可） | 観光 |
| コミュニケーション | 画像認識 | 医療・福祉 |
| 健康 | クラウド活用 | 防災 |
| 安全 | WebAPI開発 | スポーツ |
| | JavaScriptのフレームワーク / ライブラリ活用（React / Vue.js） | エンタメ |
| | | 環境・SDGs |
| | | 企業業務 |

## 企画内容

データベースと組み合わせて、次のような機能を組み込む。

- **保存**：お気に入り、履歴、マイページ
- **共有**：ランキング、レビュー、コメント
- **分析**：統計、トレンドの可視化

他チームのメンバーと一緒に、ユーザー調査として次のことを行う。

- ユーザーの声を取り入れた企画にする
- 制作途中にUIの改善などを確認してもらう
- 完成後に評価してもらい、その結果を最終プレゼンで発表する

## 制作物の条件

- 一般の方が利用することを想定する
- 展示会・発表会で紹介できる
- Windows上で動作する、PHP・Java・Python のいずれかのフレームワークを使う
- データベースを必ず使い、テーブルを3つ以上作る
- CSSフレームワーク（Bootstrap・Tailwind CSS のいずれか）を使う
- スマホに対応したレスポンシブデザインにする
- 制作物の技術説明ができる

## 単位について

後期 卒業制作Ⅱの単位は卒業条件。**落単した場合は2026年度の卒業を認めない。**

## 必須工程

1. 制作テーマの提出・説明
2. 調査書と企画書の提出・説明
3. 企画プレゼン（クラスにて）
4. スケジュール提出
5. 仕様・概要図の提出
6. 制作実態報告
7. システムテストの報告
8. レビューを受けた改訂計画の提出
9. 制作物プレゼン（クラスにて）

## プレゼン

### 目的

他クラスの学生が次の項目を評価する。プレゼン内容に共感してもらえることを意識する。

- 企画の目的が明確で分かりやすい
- 誰が何のために使う作品なのか理解できる
- 作品が実際に動くことを確認でき、デモの内容が分かりやすい（中間プレゼン以降）
- 技術やデザインで工夫した点が伝わる（中間プレゼン以降）
- 話し方（声の大きさ・スピード・抑揚など）が適切
- 発表中の態度や姿勢が良い

### ルール（想定）

| プレゼン | 日付 | 発表 | 質疑応答 |
| --- | --- | --- | --- |
| 企画プレゼン | 11/12 | 8分 | 8分 |
| 中間プレゼン（現状報告） | 1/14 | 6分 | 8分 |
| 発表会 | 2/22（予定） | 8分 | 12分 |

- プロジェクターなどを使って説明する
- 評価が上がることを意識する
- 必ずリハーサルをし、時間配分が偏らないようにする

### 出席について

- 計3回のプレゼンを行うことが単位取得の必須条件（2026年度卒業条件）。公欠1回の場合のみ計2回。
- プレゼンを欠席した場合、または就活で2回以上公欠した場合は、次回の授業でプレゼンを行う。それ以降の再プレゼンは認めない。
- 無断欠席の場合は、次回プレゼンができない場合がある。

## 評価

| 観点 | 内容 |
| --- | --- |
| 目的明確度 | 掲げた目的が、作品を使うことで明確に感じられるか |
| 完成度 | 予定通り、もしくは推測される内容まで到達しているか |
| 挑戦度 | 新規性・独創性があったか |
| 品質 | テキスト・デザイン・UI・使いやすさ・バグがないかなど基本要素の質 |
| プレゼン | 制作物に関わらず、魅力的な発表・展示か |
| チームワーク | 作業の偏りがない、チームの雰囲気、心理的安全性 |

卒業制作Ⅱでは**技術面の評価の割合を高くする**。品質の評価基準は [checklist.md](checklist.md) にまとめています。
