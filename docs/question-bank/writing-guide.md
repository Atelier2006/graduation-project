# 問題の書き方ガイド

[問題集](README.md)に問題を追加するときのルールと書き方です。人が書くときも、AIエージェント（[question-writer](../../.claude/agents/question-writer.md)）に書かせるときも、このガイドに従います。作成のルールの元は[要件定義書の5章](../requirements.md#5-問題コンテンツの要件)です。

## 1. 守るルール

| ID | ルール |
| --- | --- |
| C-01 | 実在の企業名・サービス名・ロゴ・人名を使わない。[架空ブランド](../../seed/brands.yaml)を使う |
| C-02 | URL・メールアドレスのドメインは `.example`（必要なら `.test`）だけを使う。実在のドメインは書かない |
| C-03 | 電話番号は一部を `X` で伏せる（例：`080-XXXX-XXXX`、`+1 XXX-XXX-XXXX`）。番号の始まり（080、+1など）は手がかりになるので残してよい |
| C-04 | 実際の詐欺メッセージを書き写さない。[事例集](examples.md)の特徴をもとに、自分たちで書く |
| C-05 | だます側のやり方は書かない。見抜き方と正しい行動に絞る |
| C-06 | 解説には、見るべき場所・なぜ怪しいのか（本物と言える理由）・正しい行動・参考資料の4つを必ず入れる |
| C-07 | 作った人とは別の人が確認してから公開する |
| C-08 | 必要以上に怖がらせる表現や、特定の人を傷つける表現を使わない |

確認には次のコマンドを使います（ルール違反の多くを自動で見つけます）。

```
python tools/question_bank.py check
```

## 2. 問題のファイルと番号

- 問題は `seed/questions/` のYAMLファイルに書きます。
- 番号は `Q-<画面の記号>-<3桁の連番>` です。

| 記号 | 画面の種類 | channel |
| --- | --- | --- |
| EM | メール | email |
| SM | SMS | sms |
| SN | SNSのメッセージ・投稿 | sns |
| WB | Webサイト・偽の警告画面 | web |
| AD | 広告 | ad |
| CH | 会話（電話・ビデオ通話・チャット） | chat |
| UR | URLの読み方（type: url） | （なし） |

## 3. 判定問題（type: judge）の形

```yaml
- id: Q-SM-001
  title: 不在通知を装うSMS     # 管理用の短い名前
  type: judge
  channel: sms
  is_scam: true
  level: easy                 # easy / normal / hard
  situation: S02              # seed/situations.yaml のコード
  targets: [全世代]           # 学生 / 社会人 / 高齢者 / 全世代
  brand: hashire              # なりすまされた・本物の連絡を出した架空ブランド（seed/brands.yaml の key）。
                              # 正規の連絡方法が判断の決め手になるブランドも書く。場面になったSNS・アプリというだけなら空にする
  tactics: [T01, T03, T09]    # 詐欺なら1つ以上。本物なら []
  examples: [EX-012]          # もとにした事例集の番号（1つ以上）
  context: |                  # 状況の説明（問題の前に表示する）
    ネットで買い物をした覚えはないが、家族あての荷物はよく届く。
  message:
    sender_name: ハシレ運輸   # 表示名
    sender: "080-XXXX-XXXX"   # メールアドレス・電話番号・アカウント名
    subject:                  # メールの件名（メール以外は空）
    body: |
      お客様宛にお荷物のお届けにあがりましたが不在の為持ち帰りました。配送物は下記よりご確認ください。
    link: "http://hashire-unyu.example.redelivery-check.example/r?id=XXXX"
    page_url:                 # Webのアドレスバー（Web以外は空）
    parts: []                 # Web・広告・会話・SNSの部品（4章）
  actions:                    # 3〜4個。best: true はちょうど1つ
    - text: リンクを開いて、再配達の手続きをする
    - text: メッセージのリンクは使わず、ハシレ運輸の公式アプリや不在票の番号で確かめる
      best: true
    - text: 送信元の番号に電話して確かめる
  hints:                      # 見るべき場所（1つ以上）
    - target: sender          # sender / subject / body / link / page_url / part:<番号（1から）>
      note: 個人の携帯電話の番号から届いている。
    - target: link
      note: 本当の持ち主（登録ドメイン）は redelivery-check.example。hashire-unyu.example はその前に付けた飾り。
  explanation:
    why: |
      宅配業者をかたる偽のSMSの典型。ハシレ運輸は、不在のときは紙の不在票を入れ、リンク付きのSMSは送らない。
    action: |
      荷物を待っているときでも、メッセージのリンクは開かない。公式アプリや不在票の番号から確かめる。
  references:                 # 1つ以上。事例集の出典から選ぶ
    - title: 宅配便業者をかたる迷惑メールに注意（出典のタイトル）
      url: https://...
```

## 4. 部品（parts）の書き方

**Webサイト（web）**

```yaml
parts:
  - kind: heading     # 見出し
    text: 本人確認のお願い
  - kind: text        # 文章
    text: 不正なログインを防ぐため、カード情報を再登録してください。
  - kind: form        # 入力欄
    fields: [カード番号, 有効期限, セキュリティコード]
  - kind: button
    text: 確認する
  - kind: warning     # 赤い警告の帯など
    text: お使いのパソコンはウイルスに感染しています
  - kind: phone       # 画面に出ている電話番号
    text: "050-XXXX-XXXX"
```

**広告（ad）**：`kind: ad_label`（「広告」の表示）、`heading`、`text`、`button` を使う。広告主の表示名は `message.sender_name` に書く。

**会話（chat）**

```yaml
parts:
  - kind: event       # 地の文（着信、ビデオ通話への切り替えなど）
    text: 知らない番号（+XX XXX-XXXX）から着信があった
  - kind: say
    who: 相手         # 相手 / あなた
    name: そよかぜ警察署 生活安全課を名乗る人
    text: あなたの口座が犯罪に使われています。
  - kind: say
    who: あなた
    text: え、どういうことですか？
```

**SNS（sns）**：メッセージ（DM）なら `sender_name`・`sender`（@から始まるアカウント名）・`body` を使う。アカウントの様子は `kind: profile` で書く（例：「認証バッジなし・フォロワー12人・今月作られたアカウント」）。

## 5. URL問題（type: url）の形

```yaml
- id: Q-UR-001
  title: 銀行の名前をサブドメインに入れたURL
  type: url
  is_scam: true               # このURLが、そのブランドの本物の持ち主のものでなければ true
  level: normal
  situation: S03
  targets: [全世代]
  brand: kotori
  tactics: [T03]
  examples: [EX-005]
  context: |
    コトリ銀行からのお知らせだというメールに、次のURLが書かれていた。
  url: "https://kotori-bank.example.login-secure.example/account"
  choices: [kotori-bank.example, login-secure.example, account]
  answer: login-secure.example   # このURLの登録ドメイン（本当の持ち主）
  explanation:
    why: |
      URLの本当の持ち主は、ホスト名の一番右側（登録ドメイン）で決まる。…
    action: |
      ログインは、ブックマークや公式アプリから行う。
  references:
    - title: …
      url: https://...
```

`.example` は公開リストにないドメインなので、登録ドメインは「最後の2つの区切り」（例：`login-secure.example`）になります。

## 6. 難易度の作り分け

| 難易度 | 作り方 | 例 |
| --- | --- | --- |
| easy（やさしい） | 見抜くポイントが2つ以上はっきりある | 不自然な日本語＋公式と違うドメイン＋カード番号の入力 |
| normal（ふつう） | ポイントが1〜2個で、少し注意が要る | 自然な文章だが、ドメインがつづり違い |
| hard（むずかしい） | 見た目では本物と区別しにくい。連絡の手段や状況から判断する | 送信元も文章も本物らしいが、「このブランドはSMSでリンクを送らない」ことで判断する／本物なのに急ぎの内容で怪しく見える |

- 難易度は作成者の見立てです。公開後は回答の正答率から自動で調整されます。
- hard の問題は、**見た目の細かい違い探し**にしない。「連絡の手段が公式と違う」「状況に合わない」「確かめる行動を取れば防げる」ことを学べる問題にする。

## 7. 本物の問題の作り方

詐欺と本物の割合はおよそ6：4にします。本物の問題を入れないと、「全部詐欺と答えれば正解」になってしまうからです。

本物の問題の型：

1. **公式の手段で届いた普通の連絡**：公式アプリの通知、公式ドメインからの注文確認メール（ログインや入力を求めない）。
2. **急ぎだが本物**：カードの不正利用の疑いを知らせる公式アプリの通知（裏面の番号に電話するよう案内する）。
3. **自分の操作に続いて届いたもの**：自分でログインした直後に届いた認証番号のSMS。
4. **本物の公的な案内**：市役所からの郵送の案内を、市の公式サイトで確かめられるもの。

本物の問題でも、行動の最善は「公式アプリやブックマークから確かめる」になることが多いです。「本物でも、大事な手続きは公式から」を学べるようにします。

## 8. 行動の選択肢の標準セット

問題ごとに、次から3〜4個を選んで使います（文言は問題に合わせて少し変えてよい）。最善はちょうど1つにします。

| 記号 | 選択肢 | 主に最善になる問題 |
| --- | --- | --- |
| A1 | リンクを開いて、案内どおりに手続きする | 最善にならない |
| A2 | 書かれている電話番号に電話して確かめる | 最善にならない |
| A3 | メッセージのリンクは使わず、公式アプリやブックマーク・正規の窓口から確かめる | 多くの問題（本物の問題も含む） |
| A4 | 返信して事情を聞く | 最善にならない |
| A5 | 何もせずに削除する（無視する） | 明らかな詐欺で、確かめる必要もないもの |
| A6 | 家族や相談窓口（警察相談専用電話 #9110、消費者ホットライン 188 など）に相談する | 電話や会話で迫られている場面 |
| A7 | 言われたとおりにお金を払う（電子マネーを買う） | 最善にならない |
| A8 | 画面の案内どおりにソフトを入れる・操作する | 最善にならない |
| A9 | 画面を閉じる（閉じられなければブラウザを終了する） | 偽の警告画面 |
| A10 | 公式サイトで同じ情報が出ているか確かめてから使う | 広告・SNSの投稿 |

## 9. 文章の書き方

- 解説は短い文で、中学生でも読める言葉にする。専門用語には説明を添える（例：登録ドメイン＝URLの本当の持ち主）。
- 架空ブランドの「正規の連絡方法」（[brands.yaml](../../seed/brands.yaml) の official_contact）と食い違わないようにする。
- 詐欺のメッセージの本文は、やさしい問題では不自然な日本語を入れてもよい。むずかしい問題では自然な日本語にする。
- `context`（状況）は、判断に必要なときに書く。例：「自分でログインした直後」「荷物を待っている」。
- 参考資料には、事例集の出典から公的機関などのページを選ぶ。
