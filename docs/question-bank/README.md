# 問題集

「ネット詐欺見抜きトレーニング」（[要件定義書](../requirements.md)）で使う練習問題の案と、そのもとにした事例集です。アプリの初期データ（要件定義書 [3.1節](../requirements.md#31-必須mvp)の「初期の問題40問」）は、ここから選んで仕上げます。

> **問題はすべて架空です。** 会社・サービス・URL・電話番号は実在しません（[作成のルール](writing-guide.md#1-守るルール)）。
>
> **公開の前に、チームの人が確認します。** 問題案と事例集はAIエージェントが作り、作成者とは別のAIエージェントが確認したものです。[7章](#7-公開前に人が確かめること)の点を、人が確かめてから使ってください。

## 2. 作り方

### 2.1 流れ

| 段階 | 担当 | やったこと |
| --- | --- | --- |
| 1. 事例を集める | 調査エージェント5体（R1〜R5） | 公的機関などの注意喚起をWeb検索で集め、手口の流れ・見抜くポイント・正しい行動・本物の連絡の特徴を、出典つきでまとめた（92件） |
| 2. 事例集にまとめる | 取りまとめ（Claude） | 重なっていた4組をまとめ、シチュエーション順に EX-001〜EX-088 の番号を付けた |
| 3. 問題を書く | 作成エージェント4体（W1〜W4） | 担当表（画面の種類 × シチュエーション × 難易度 × 詐欺か本物か）に沿って、架空ブランドで問題を書いた |
| 4. 確かめる | 確認エージェント3体（RV1〜RV3）と自動チェック | 作成者とは別のエージェントが、正解・最善の行動・解説・参考資料・安全のルールを確かめて直した |
| 5. 書き出す | ツール | questions.md と examples.md を作った |

AIエージェントの役割は [.claude/agents/](../../.claude/agents/) に定義してあり、チームが問題を増やすときにも同じものを使えます。

| エージェント | 役割 |
| --- | --- |
| [scam-example-researcher](../../.claude/agents/scam-example-researcher.md) | 注意喚起から事例を集め、事例集に足す |
| [question-writer](../../.claude/agents/question-writer.md) | 事例をもとに、架空ブランドで問題を書く |
| [question-reviewer](../../.claude/agents/question-reviewer.md) | 作成者とは別の目で、問題を確かめて直す |

## 3. 分類の軸

問題は、次の6つの軸で分類しています。チャレンジの出題や、統計（要件定義書 F-13）にも使います。

| 軸 | 値 | 説明 |
| --- | --- | --- |
| 正解 | 詐欺 / 本物 | およそ6：4。「全部詐欺と答えれば正解」にならないように本物を入れる |
| 難易度 | やさしい / ふつう / むずかしい | 作り分けは[書き方ガイド6章](writing-guide.md#6-難易度の作り分け)。むずかしい問題は細かい違い探しにせず、連絡の手段や状況で判断させる |
| 画面の種類 | メール / SMS / SNS / Webサイト / 広告 / 会話 / URLの読み方 | 要件定義書 [5.1節](../requirements.md#51-画面の種類) |
| シチュエーション | S01〜S18 | どんな場面で出会うか（[seed/situations.yaml](../../seed/situations.yaml)） |
| 手口 | T01〜T15 | 詐欺の問題だけに付ける。1問に複数（[seed/tactics.yaml](../../seed/tactics.yaml)） |
| 対象 | 学生 / 社会人 / 高齢者 / 全世代 | 特に気をつけてほしい人 |

## 6. 問題を増やす・直すとき

1. [書き方ガイド](writing-guide.md)に沿って、`seed/questions/` のYAMLに書く（番号は画面の種類ごとの続き）。もとにした事例（`examples`）と参考資料（`references`）を必ず付ける。
2. ルールを確かめる：`python tools/question_bank.py check`（1ファイルだけなら `--file seed/questions/sms.yaml`）。エラーが0件になるまで直す。
3. 作った人とは別の人が確認する（C-07）。
4. `python tools/question_bank.py render` で questions.md と examples.md を作り直して、コミットする。

事例や問題の番号は `python tools/question_bank.py show EX-001 Q-SM-001` で表示できます。

Claude Code では、[.claude/agents/](../../.claude/agents/) のエージェントに頼めます（例：「question-writer エージェントで、S10 恋愛・出会いの本物の問題を2問足して」）。

### 7.1 出典

1. 出典は、Web検索の結果（検索結果の要約）で確かめたものです。作業環境の制約で、ページそのものは開けていません。公開する前に、問題の参考資料に使った出典を開いて、題名・内容・日付を確かめてください。
2. 題名が正式でない出典（「（題名未確認）」「（ページ名未確認）」「（題名は要約）」や、かっこ書きの説明だけのもの）は、アプリの解説にそのまま表示されます。正式な題名に直したら、`examples.yaml` と問題の `references` の両方を直します（片方だけ直すと、ツールが「注意」で知らせます）。
3. 一部の出典は古いもの（2010〜2019年）です。新しい注意喚起があれば差し替えます。被害の件数や金額などの数字は、出典の時点のものです。
4. 調査の途中で検索の回数の上限に達したため、次の点は調べきれていません。
   - 本物の再配達の通知の見え方
   - 本物のセキュリティ警告と、多要素認証の通知の見え方
   - カード裏面の番号で確かめる方法
   - 警察・年金事務所が電話でお金を求めないこと（一部）
   - 公的な出典が見つからなかったテーマ（ゲーム内通貨の無料配布、内定者への研修費の請求、奨学金についての新しい注意喚起）
